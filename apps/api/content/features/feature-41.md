<h2>Ziel / Zweck</h2><p>Dieses Feature führt Zwei-Faktor-Authentisierung (2FA) via Google Authenticator (TOTP) als Sicherheitsebene beim Login ein. Alle Benutzer (Admin, Disponent, Reader) müssen sich nach dem Passwort zusätzlich mit einem zeitbasierten 6-stelligen Code aus der Google Authenticator App authentisieren.</p><h2>Fachliche Beschreibung</h2><p>Jeder Benutzer kann Google Authenticator aktivieren, indem er in den persönlichen Sicherheitseinstellungen einen QR-Code mit seiner Google Authenticator App (oder jeder anderen TOTP-kompatiblen App) scannt. Das System generiert dazu ein zufälliges Base32-kodiertes Geheimnis und zeigt dieses als QR-Code an.</p><p>Nach erfolgreicher Aktivierung ist beim Login ein 6-stelliger Code erforderlich, den die App alle 30 Sekunden neu generiert. Das System validiert diesen Code serverseitig gegen das für den Benutzer gespeicherte Geheimnis.</p><p>Der Benutzer kann Google Authenticator jederzeit deaktivieren. Ein Administrator kann das Geheimnis eines anderen Benutzers regenerieren (notwendig z.B. bei Geräteverlust).</p><p><strong>Scope-Eingrenzung:</strong> Backup-Codes sind nicht Implementierungsscope dieses Features. Das Datenbankfeld <code>totp_backup_codes</code> wird als reserviertes JSON-Array angelegt und verschlüsselt, die Funktionalität wird aber zu einem späteren Zeitpunkt als separate Erweiterung hinzugefügt.</p><h2>Regeln &amp; Randbedingungen</h2><p><strong>Aktivierung &amp; Geheimnis</strong></p><ul class="tight" data-tight="true"><li><p>Das TOTP-Geheimnis wird verschlüsselt in der Datenbank gespeichert (<code>users.totp_secret</code>).</p></li><li><p>Das Geheimnis wird nur einmalig bei der Aktivierung angezeigt (im QR-Code, optional auch als Text-Fallback).</p></li><li><p>Ein Benutzer kann sein Geheimnis jederzeit durch Deaktivierung und Neuaktivierung erneuern.</p></li><li><p>Ein Benutzer kann sein Geheimnis nicht selbst neu generieren; nur ein Administrator kann das für ihn tun.</p></li></ul><p><strong>Login-Fluss</strong></p><ul class="tight" data-tight="true"><li><p>Der Login erfolgt in zwei Schritten: (1) Passwort/Benutzername, (2) 6-stelliger Code.</p></li><li><p>Wenn <code>totp_enabled = true</code>, ist der Code beim Login zwingend erforderlich.</p></li><li><p>Das System blockiert den Login, wenn der Code nicht eingegeben oder falsch eingegeben wird.</p></li><li><p>Der Code wird gegen ein Zeitfenster von ±30 Sekunden validiert (Standard TOTP).</p></li></ul><p><strong>Datenschutz</strong></p><ul class="tight" data-tight="true"><li><p>Das Geheimnis wird mit einem anwendungsweiten Verschlüsselungsschlüssel verschlüsselt gespeichert.</p></li><li><p>Der Benutzer sieht das Geheimnis nicht erneut nach der Aktivierung.</p></li></ul><p><strong>Backup-Codes (Scope-reserviert, nicht implementiert)</strong></p><ul class="tight" data-tight="true"><li><p>Das Feld <code>users.totp_backup_codes</code> (TEXT, JSON-Array, verschlüsselt) wird angelegt.</p></li><li><p>Backup-Codes sind NOT Teil dieses Features.</p></li></ul><p></p>
