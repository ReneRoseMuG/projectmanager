<h2>Backup &amp; Synchronisation</h2><h3>Ziel / Zweck</h3><p>Das Feature ermöglicht es dem Administrator, den gesamten Datenbestand des Projekt Managers — Datenbankinhalt und alle Anhänge — gesichert, wiederherstellbar und bei Bedarf automatisch mit einem entfernten SFTP-Server abgeglichen zu halten. Es schützt vor Datenverlust und erlaubt den Umzug auf eine andere Instanz ohne manuellen Aufwand.</p><h3>Fachliche Beschreibung</h3><p>Der Administrator hat zwei Sicherungswege zur Verfügung:</p><p><strong>Vollsicherung</strong><br>Eine Vollsicherung erstellt einen vollständigen Schnappschuss des Systems: alle Datenbankzeilen aus sämtlichen Tabellen sowie alle hochgeladenen Dateien und Inhalte. Das Ergebnis ist eine einzelne ZIP-Datei, die lokal gespeichert wird. Optional wird diese Datei anschließend automatisch auf den konfigurierten SFTP-Server hochgeladen. Die Sicherungsdatei enthält ein Prüfsummenmanifest, über das die Integrität beim Import verifiziert wird. Während der Erstellung und des Uploads erhält der Benutzer laufende Fortschrittsmeldungen.</p><p><strong>Inkrementelle Synchronisation</strong><br>Die inkrementelle Synchronisation überträgt nur Änderungen seit dem letzten Abgleich auf den SFTP-Server — geänderte Dateien werden hochgeladen, gelöschte entfernt, die Datenbankdaten bei Änderung neu übertragen. Alle Dateioperationen laufen innerhalb einer einzigen SFTP-Sitzung, um Verbindungsaufbau-Overhead zu minimieren. Das Manifest auf dem Server wird immer aktualisiert und dient als Grundlage für einen späteren Import. Der Fortschritt (Vergleich, Upload, Löschung) wird dem Benutzer in Echtzeit angezeigt.</p><p><strong>Import &amp; Wiederherstellung</strong><br>Vor jedem Import zeigt das System eine Vorschau: welche Tabellen und Dateien übernommen werden, ob Schema-Versionen übereinstimmen und ob Blockiergründe vorliegen. Der Administrator muss die Übernahme durch eine Bestätigungsphrase explizit freigeben. Während des Imports sichert das System den aktuellen Zustand automatisch, sodass ein Rollback möglich bleibt. Nach dem Import wird die Integrität der wiederhergestellten Daten über Prüfsummen verifiziert.</p><h3>Regeln &amp; Randbedingungen</h3><ul class="tight" data-tight="true"><li><p>Eine Vollsicherung und ein inkrementeller Sync können nicht gleichzeitig ausgeführt werden.</p></li><li><p>Der Import ist nur möglich, wenn Schema-Version der Sicherungsdatei und Zielinstanz übereinstimmen.</p></li><li><p>Das Bestätigungswort beim Import muss exakt eingegeben werden; keine Abweichung wird akzeptiert.</p></li><li><p>Remotedateien, die bereits importiert wurden, können kein zweites Mal importiert werden.</p></li><li><p>SFTP-Verbindungsdaten (Host, Benutzer, Passwort, Verzeichnis) müssen vollständig konfiguriert sein, bevor ein Remote-Abgleich möglich ist.</p></li><li><p>Das Remote-Verzeichnis muss vom Administrator explizit als geschützt bestätigt worden sein.</p></li><li><p>Anhänge und Inhalte werden SHA-256-geprüft; abweichende Prüfsummen blockieren den Import.</p></li><li><p>Der inkrementelle Sync hält für die gesamte Dauer des Abgleichs eine einzige SFTP-Verbindung offen — keine separate Verbindung pro Datei.</p></li><li><p>Fortschrittsevents werden über den Realtime-Bus an verbundene Clients gesendet.</p></li></ul><h2>Architektur &amp; Kontext</h2><h3>Betroffene Schema-Objekte</h3><p>Sicherungsdatei (lokal) — ZIP-Archiv mit Datenbankinhalt, Anhängen und Prüfsummenmanifest, gespeichert im konfigurierten Arbeitsverzeichnis.</p><p>Remote-Sicherungsdatei — dieselbe ZIP-Datei, übertragen auf den SFTP-Server; enthält Importhistorie zur Duplikatserkennung.</p><p>Inkrementelles Sync-Manifest — JSON-Datei auf dem SFTP-Server, die den letzten bekannten Zustand (Tabellen-Hashes, Datei-Hashes) beschreibt.</p><p>Importhistorie — systeminterner Eintrag, der bereits importierte Remote-Dateien vermerkt und Doppel-Importe verhindert.</p><h3>Verwandte Features &amp; Abhängigkeiten</h3><ul class="tight" data-tight="true"><li><p>Einstellungen / SFTP-Konfiguration — Host, Port, Benutzer, Passwort und Remote-Verzeichnis werden dort gepflegt und sind Voraussetzung für alle Remote-Operationen.</p></li><li><p>Anhänge — Alle hochgeladenen Dateien werden in die Sicherung einbezogen; das Anhang-Verzeichnis ist Teil der Prüfsummenverifizierung.</p></li><li><p>Realtime-Bus — Fortschrittsevents des Backups werden über denselben SSE-Kanal gesendet, der auch für Dateninvalidierungen genutzt wird.</p></li></ul><p></p>
