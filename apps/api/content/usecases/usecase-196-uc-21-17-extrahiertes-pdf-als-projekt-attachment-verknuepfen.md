<h1>UC 21/17: Extrahiertes PDF als Projekt-Attachment verknüpfen</h1>
<h2>Metadaten</h2>
<ul><li>Feature: <a href="../ft-21-dokumentenextraktion.md">FT (21): Dokumentenextraktion</a></li></ul>
<h2>Akteur</h2>
<p>System</p>
<h2>Ziel</h2>
<p>Nach erfolgreicher Projektanlage das extrahierte PDF als <code>project_attachment</code> des neu angelegten Projekts persistieren. Duplikat-Verdacht transparent prüfen und dem Akteur im Projekt-Speichern-Review eine Entscheidungsmöglichkeit bieten.</p>
<h2>Vorbedingungen</h2>
<ul><li>Ein Doc Extract wurde durchgeführt (UC 21/01 bis UC 21/04)</li><li>Ein neues Projekt wurde erfolgreich angelegt (UC 21/09 oder UC 21/10)</li><li>Das extrahierte PDF existiert und ist technisch zugänglich</li><li>Die Projekt-ID des neu angelegten Projekts ist verfügbar</li></ul>
<h2>Ablauf</h2>
<p>1. Das System hat ein neues Projekt erfolgreich persistiert (UC 21/09 oder UC 21/10)<br>2. Das System greift auf das extrahierte PDF zu (Dateiname und Dateigröße sind bekannt)<br>3. Das System führt im Projekt-Speichern-Review eine Duplikat-Prüfung durch:</p>
<ul><li>Query <code>customer_attachment</code>: Existiert ein Eintrag mit gleichem <code>original_filename</code>?</li><li>Query <code>project_attachment</code>: Existiert ein Eintrag mit gleichem <code>original_filename</code>?</li><li>Query <code>employee_attachment</code>: Existiert ein Eintrag mit gleichem <code>original_filename</code>?</li></ul>
<p>4. Falls Duplikat gefunden: Das System zeigt dem schreibberechtigten Akteur einen Review-Schritt: „Eine Datei mit diesem Namen existiert bereits bei [Kunde/Projekt/Mitarbeiter]. Trotzdem verknüpfen?&quot;<br>5. Bei Button „Ja, verknüpfen&quot;: Das System fährt mit Schritt 7 fort<br>6. Bei Button „Nein, abbrechen&quot;: Das System zeigt Info-Nachricht „Projekt angelegt. Dokumentverknüpfung wurde übersprungen.&quot; und beendet den Prozess ohne Attachment-Persistierung<br>7. Falls kein Duplikat gefunden: Das System persistiert das Attachment direkt<br>8. Das System speichert die Attachment-Metadaten:</p>
<ul><li><code>project_id</code>: ID des neu angelegten Projekts</li><li><code>original_filename</code>: Dateiname des PDF (z.B. „Auftrag_12345.pdf&quot;)</li><li><code>persistent_filename</code>: Eindeutig generiert vom System (FT (19))</li><li><code>mime_type</code>: „application/pdf&quot;</li><li><code>file_size</code>: Größe in Bytes</li><li><code>created_at</code>: Jetzt</li></ul>
<p>9. Das System zeigt Erfolgs-Meldung: „Projekt angelegt und Dokument verknüpft.&quot;</p>
<h2>Alternativen</h2>
<ul><li>PDF-Datei existiert nicht mehr → System loggt Fehler, zeigt Warnung: „Projekt angelegt, aber Dokumentverknüpfung nicht möglich (Datei nicht erreichbar). Sie können das Dokument manuell hochladen.&quot;</li><li>Duplikat-Query schlägt fehl (Datenbankfehler) → System loggt Fehler, Attachment wird trotzdem versucht zu persistieren (fail-safe), User-Feedback: „Projekt angelegt, Dokumentprüfung fehlgeschlagen, Dokument wurde trotzdem verknüpft.&quot;</li><li>Attachment-Persistierung schlägt fehl → System loggt Fehler, zeigt Warnung: „Projekt angelegt, aber Dokumentverknüpfung ist fehlgeschlagen. Sie können das Dokument manuell hochladen.&quot;</li><li>Akteur lehnt Duplikat ab → Kein Attachment wird persistiert, Projekt bleibt bestehen</li></ul>
<h2>Ergebnis</h2>
<p>Das extrahierte PDF ist als <code>project_attachment</code> des neu angelegten Projekts persistiert. <code>original_filename</code> und Metadaten sind korrekt gespeichert. Das Attachment ist im Projekt-Sidebar abrufbar. Es entstehen keine unbewusst doppelten Attachments. Der schreibberechtigte Akteur hat volle Kontrolle über Duplikat-Entscheidungen.</p>
