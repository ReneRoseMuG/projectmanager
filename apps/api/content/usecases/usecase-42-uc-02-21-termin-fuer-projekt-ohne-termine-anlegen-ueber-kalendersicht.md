<h1>UC 02/21: Termin für Projekt ohne Termine anlegen (über Kalendersicht)</h1>
<h2>Metadaten</h2>
<ul><li>Feature: <a href="../ft-02-projekte.md">FT (02): Projekte</a></li></ul>
<h2>Akteur</h2>
<p>Disponent, Administrator</p>
<h2>Ziel</h2>
<p>Aus der Projektliste „Ohne Termine&quot; direkt in die Kalenderansicht navigieren und einen Termin mit Projekt-Vorbefüllung anzulegen.</p>
<h2>Vorbedingungen</h2>
<ul><li>Projektliste wird in Ansicht „Ohne Termine&quot; angezeigt</li><li>Projekt hat keine zugeordneten Termine</li><li>Akteur besitzt Berechtigung zur Terminanlage</li><li>Der Akteur ist authentifiziert</li></ul>
<h2>Ablauf</h2>
<p>1. Der Akteur öffnet die Projektübersicht.<br>2. Der Akteur betätigt den Umschalter „Ohne Termine&quot;.<br>3. Das System lädt ausschließlich Projekte ohne Termine.<br>4. Das System rendert die Tabelle mit Spalten: Titel | Kunde | Auftragsnummer | (Button: „Termin planen&quot;)<br>5. Der Akteur sieht für jede Zeile einen Button <strong>„Termin planen&quot;</strong> (primär, grün, rechts in der Zeile).<br>6. Der Akteur klickt auf den Button „Termin planen&quot; für ein Projekt seiner Wahl.<br>7. Das System speichert die <strong>Projekt-ID</strong> im Client-Kontext (URL-Parameter oder Session-Storage).<br>8. Das System lädt die <strong>wöchentliche Kalenderansicht</strong> (FT 03 – Kalenderansichten) in den Vordergrund.<br>9. Der Akteur betrachtet die Wochenansicht und identifiziert einen gewünschten Tag.<br>10. Der Akteur klickt auf einen <strong>Wochentag</strong> (oder eine freie Zeitslot an diesem Tag).<br>11. Das System öffnet das <strong>Terminformular</strong> (Terminanlage-Dialog oder -Seite) mit folgender Vorbefüllung:</p>
<ul><li><code>project_id</code>: Aus der Projektliste (Schritt 6)</li><li><code>customer_id</code>: Vom Projekt abgeleitet</li><li><code>project_title</code>: Optional vom Projekttitel</li><li><code>project_description</code>: Vom Projekt (Beschreibung / Artikelliste)</li><li><code>start_date</code>: Vom Kalender-Klick (nur das Datum, z. B. 15.03.26)</li><li>Weitere Felder (Mitarbeiter, Notizen, Durationen, etc.): Leer oder mit Applikations-Defaults</li></ul>
<p>12. Der Akteur bearbeitet das Terminformular nach Bedarf:</p>
<ul><li>Zeit eingeben oder korrigieren (expliziter Klick auf „Startzeit&quot; demaskiert das Eingabefeld)</li><li>Mitarbeiter zuordnen</li><li>Notizen hinzufügen</li><li>Weitere optionale Felder ausfüllen</li></ul>
<p>13. Der Akteur klickt <strong>„Speichern&quot;</strong> (oder „Termin anlegen&quot;).<br>14. Das System validiert das Formular gemäß den Regeln aus FT (05) oder dem Termin-Domänenmodell.<br>15. Das System persistiert den Termin mit allen Feldern.<br>16. Das System aktualisiert die Projekt-Referenz: Das Projekt ist nun mit einem Termin verknüpft.<br>17. Das System kehrt <strong>automatisch zur Projektliste zurück</strong>.<br>18. Das System lädt die Projektliste neu.<br>19. Das gerade bearbeitete Projekt verschwindet aus der Ansicht „Ohne Termine&quot; (weil es jetzt einen Termin besitzt).<br>20. Das System bleibt in der Ansicht „Ohne Termine&quot;, zeigt aber nur noch die verbleibenden Projekte ohne Termine an.<br>21. Der Akteur kann den Prozess für weitere Projekte wiederholen (Schritt 5–20).</p>
<h2>Alternativen</h2>
<p><strong>Alternative A – Kalenderwahl wird abgebrochen:</strong></p>
<ul><li>Der Akteur schließt die Kalenderansicht, ohne einen Tag zu klicken.</li><li>Das System kehrt zur Projektliste „Ohne Termine&quot; zurück.</li><li>Das Projekt bleibt unverändert in der Liste.</li></ul>
<p><strong>Alternative B – Terminformular wird abgebrochen:</strong></p>
<ul><li>Der Akteur öffnet das Terminformular, ändert Werte, bricht aber ab, ohne zu speichern.</li><li>Das System schließt das Formular.</li><li>Das System kehrt zur Kalenderansicht zurück (optional) oder zur Projektliste.</li><li>Das Projekt bleibt unverändert in der Liste „Ohne Termine&quot;.</li></ul>
<p><strong>Alternative C – Validierungsfehler beim Speichern:</strong></p>
<ul><li>Der Akteur versucht, das Formular zu speichern, aber ein Pflichtfeld ist nicht gefüllt.</li><li>Das System zeigt eine Fehlermeldung und markiert das betroffene Feld.</li><li>Das Formular bleibt offen, der Akteur kann den Fehler korrigieren.</li><li>Das Projekt bleibt unverändert in der Liste.</li></ul>
<p><strong>Alternative D – Technischer Fehler während Persistierung:</strong></p>
<ul><li>Beim Speichern des Termins tritt ein Fehler auf (z. B. Datenbankfehler).</li><li>Das System zeigt eine Fehlermeldung.</li><li>Das System kehrt zum Terminformular zurück (oder zur Kalenderansicht).</li><li>Das Projekt bleibt unverändert in der Liste „Ohne Termine&quot;.</li></ul>
<p><strong>Alternative E – Projekt wurde zwischenzeitlich gelöscht:</strong></p>
<ul><li>Der Akteur war in der Kalenderansicht, während ein anderer Akteur das Projekt löschte.</li><li>Das System erkennt beim Speichern des Termins, dass das Projekt nicht mehr existiert.</li><li>Das System blockiert mit einer Fehlermeldung (z. B. 409 Conflict oder 404 Not Found).</li><li>Das System kehrt zur Projektliste zurück.</li></ul>
<p><strong>Alternative F – Projekt wurde zwischenzeitlich mit einem Termin versehen:</strong></p>
<ul><li>Der Akteur war lange in der Kalenderansicht inaktiv.</li><li>Ein anderer Akteur hat dem gleichen Projekt einen Termin zugeordnet.</li><li>Das System erkennt beim Speichern, dass das Projekt bereits einen Termin hat.</li><li>Das System blockiert mit einer Fehlermeldung (z. B. 409 Conflict).</li><li>Das System informiert den Akteur.</li><li>Das System kehrt zur Projektliste zurück, wo das Projekt nicht mehr in „Ohne Termine&quot; sichtbar ist.</li></ul>
<p><strong>Alternative G – Projekt hat sich geändert:</strong></p>
<ul><li>Während der Akteur im Terminformular war, hat ein anderer Akteur das Projekt bearbeitet (z. B. Titel geändert).</li><li>Das System kann optional:</li><li>Die neuen Projektdaten automatisch ins Formular einfließen lassen (optimistisch), oder</li><li>Den Akteur warnen und zum Neuladen auffordern (pessimistisch).</li><li>Diese Entscheidung hängt von der allgemeinen Versionierungs-Strategie ab (siehe FT 02 UC 02/09).</li></ul>
<h2>Ergebnis</h2>
<ul><li>Ein neuer Termin ist persistent angelegt.</li><li>Der Termin ist dem Projekt zugeordnet.</li><li>Das Projekt ist mit mindestens einem Termin verknüpft.</li><li>Das Projekt verschwindet aus der Ansicht „Ohne Termine&quot;.</li><li>Das Projekt kann nun in „Aktuelle Projekte&quot; sichtbar sein (sofern der Termin-Startdatum ≥ heute ist).</li><li>Alle Projekt-Details (Kunde, Beschreibung, Anhänge, Notizen) bleiben unverändert.</li><li>Der Termin ist in allen Terminansichten (Kalender, Tabelle, etc.) sichtbar.</li><li>Es existiert keine widersprüchliche oder verwaiste Referenz zwischen Projekt und Termin.</li></ul>
